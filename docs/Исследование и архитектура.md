# Исследование исходников

Исследование выполнено чтением XML внутри всех трех XLSX до реализации парсера.
Воспроизводимый скрипт: `tools/inspect_sources.py`, полный протокол: `source-inspection.txt`.

Оба исходника имеют заголовки в строке 2, объединенные до строки 8.
Начала граф: E, I, AI, AU, BB, BK, BO, BS, BX. Это наблюдение, а не конфигурация парсера.
Обычные ячейки объединены по горизонтали и на три физических строки по вертикали.
Исходник 1 содержит 6 листов, исходник 2 — 7. Порядок листов значим.
Заголовки содержат переносы внутри слов («изме- ре- ния», «Приме- чание»).
Первый лист имеет большой штамп с строки 88, остальные — с 104.
Вертикальные служебные надписи в C76 и C86 находятся рядом с действительными данными
и не должны завершать таблицу. Штамп определяется по пересечению объединений с несколькими
логическими графами и служебным полям внутри границ таблицы.

В Исходнике 1 количество может находиться посреди многострочного описания.
ШУ1/ШУ3 и ШУ2/ШУ4 — несколько обозначений одной записи, а не новые записи.
Новая позиция нередко начинается номером в наименовании при пустой графе «Поз.».
Эти номера остаются частью исходного текста, искусственная нумерация не создается.
В Исходнике 2 группа «Фиксатор» продолжается с листа 3 на лист 4.
У МШП1-10-120 нет единицы измерения, она наследуется внутри группы стоек.
Масса бывает числом и текстом с десятичной запятой. Пустая масса не наследуется.

## Внутренняя модель

- ExcelReader / CellValueResolver: материализованные значения, координаты, объединения,
  кэш формул. Одно объединение количества дает один якорь.
- SourceLayoutDetector: нормализованные тексты заголовков, диапазоны граф, граница заголовка.
- SpecificationParser: поток физических строк всех листов → блоки → исполнения.
  Отдельный классификатор разделов. Контекст сбрасывается на новой позиции или разделе.
- Одно количество в блоке: объединить все строки, включая строки после количества.
- Несколько количеств: общий префикс плюс собственное исполнение, единица внутри блока;
  неоднозначные промежуточные строки сохраняются с предупреждением.
- Результат хранит источник строки и текстовые значения количества/массы отдельно от числовых.
  Это позволяет сохранить необычные значения без подмены нулем.
- WPF/MVVM: фоновый разбор, редактируемый просмотр, отдельное сохранение, журнал.

Парсер детерминированный; дополнительные семейства форм можно поддержать заменой
классификатора/детектора без изменения интерфейса и экспортера.
