# SpecConvert

Локальный конвертер Excel-спецификаций для Windows. C# / .NET 10 / WPF / MVVM,
ClosedXML 0.105.0 (MIT), установленный Microsoft Excel не требуется.

## Запуск

Открыть `SpecConvert.slnx` в Visual Studio 2026 и выбрать стартовым проектом
`src/SpecConvert.App`. Или выполнить:

```powershell
dotnet restore
dotnet run --project src/SpecConvert.App
```

1. Выберите исходный `.xlsx` и нажмите **Преобразовать**.
2. Проверьте журнал и строки предпросмотра. Двойной щелчок по ячейке позволяет исправить значение.
   Наведите указатель на строку, чтобы увидеть исходный лист и номер строки.
3. Нажмите **Сохранить XLSX**, подтвердите путь в диалоге.
4. Кнопка **Открыть результат** открывает сохраненный файл в приложении по умолчанию.

Исходная книга не перезаписывается. Изменение исходного пути сбрасывает старый просмотр.
Логи с датой, исходным путем, графами, предупреждениями и исключениями находятся в
`%LOCALAPPDATA%/SpecConvert/Logs`. Конвертация и экспорт выполняются в фоне.
Во время обработки редактирование заблокировано. Интернет при работе не нужен.

## Сборка и тесты

```powershell
dotnet build -c Release
dotnet test
dotnet publish src/SpecConvert.App -c Release --no-self-contained -o outputs/app
```

Публикация требует установленного **.NET Desktop Runtime 10** на целевом компьютере.
Для автономной поставки с включенным runtime:

```powershell
dotnet publish src/SpecConvert.App -c Release -r win-x64 --self-contained true -o outputs/standalone
```

Первое восстановление NuGet и скачивание runtime для автономной поставки могут требовать сети.
Интеграционные тесты используют локальные оригиналы в `docs` и записывают результаты в `outputs`.
Excel-файлы с данными и извлеченный из них `source-inspection.txt` не хранятся в текущей
версии репозитория. Перед запуском интеграционных тестов поместите в `docs` файлы
`Исходник 1.xlsx` и `Исходник 2.xlsx`. Для повторного исследования шаблона также нужен
`Целевая форма.xlsx`. Эти файлы исключены через `.gitignore`.

## Устройство

- `SpecConvert.Core`: модели, чтение, разрешение объединений, поиск заголовков,
  классификатор разделов, парсер блоков, экспорт.
- `SpecConvert.App`: WPF, MainViewModel, команды и файловые диалоги.
- `SpecConvert.Tests`: unit-тесты и интеграция на обоих исходниках.
- `SpecConvert.App.Tests`: загрузка окна и привязки редактирования на STA-потоке.
- `docs/Исследование и архитектура.md`: наблюдения до реализации.

## Ограничения первой версии

Парсер рассчитан на семейство форм из задания: заголовки логических граф начинаются
на одной физической строке (могут быть объединены по вертикали и горизонтали).
Сильно отличающаяся форма требует расширения SourceLayoutDetector/SectionClassifier.
Лист без распознаваемого заголовка пропускается с предупреждением, поэтому журнал
нужно проверять даже при совпадении счетчиков количеств и позиций.

Текст без количества внутри блока может относиться к предыдущему или следующему исполнению.
Парсер сохраняет текст и предупреждает о неоднозначных многострочных исполнениях.
Служебные объединения, пересекающие графы справа от наименования, обозначают начало штампа
для текущего семейства форм. Новые формы с такими объединениями внутри данных требуют адаптации.
Читается сохраненный результат формулы; если кэша нет, сохраняется диагностический текст
и выводится предупреждение. Самостоятельный полный пересчет Excel не выполняется.
Номера внутри наименования сохраняются там же; новые номера в графе «Поз.» не создаются.
